## 3.3 Estrutura do Programa

O código foi dividido em funções, permitindo separar cada etapa do processo.

A estrutura principal é composta por:


## 3.5 Explicando o codigo

---
### 3.5.1 Gerar dos Dados de Telemetria

`dados_telemetria()` é responsável por criar os dados

```text
def dados_telemetria():
    return {
        "DATA": datetime.now().strftime("%d/%m/%Y"),
        "T_INT": round(random.uniform(10, 35), 2),
        "T_EXT": round(random.uniform(-60, 60), 2),
        "STR": random.randint(0, 1),
        "PWR": round(random.uniform(50, 100), 2),
        "PRS": round(random.uniform(100, 350), 2),
        "MOD": random.choice(["OK", "FALHA"])"])
}
```

> Os valores são armazenados em um dicionário, permitindo identificar cada informação através de uma chave.

---

### 3.5.2 Exibição da Telemetria

Após a geração dos dados, a função `exibir_telemetria()` apresenta as informações.

```text
def exibir_telemetria(dados):

    print("==================================================")
    print(" 2.RECEBIMENTO DOS DADOS")
    print("==================================================")
    print(" ")

    print(f"Data:{dados['DATA']}")
    print(f"Temperatura interna: {dados['T_INT']}")
    print(f"Temperatura externa: {dados['T_EXT']}")

    print(f"Nível de energia: {dados['PWR']}")
    print(f"Pressão dos tanques: {dados['PRS']}")
    print(f"Módulos críticos: {dados['MOD']}")
```
---
### 3.5.3 Validação dos Parâmetros

A função `validar_parametros()` implementa os critérios definidos na [Parte 1 — Telemetria e Parâmetros Operacionais.](https://github.com/stela92s/aurora-siger-pre-decolagem/blob/main/docs/2.algoritimo.md)

Inicialmente são criadas duas variáveis:

```text
falhas = []
sistema_ok = True
```

A lista `falhas` será utilizada para armazenar os parâmetros que apresentarem condições `NOK`.

A variável `sistema_ok` começa como `True`, assumindo que o sistema está dentro das condições estabelecidas.

Quando uma falha é identificada:

```text sistema_ok = False ```

> Dessa maneira, uma única condição fora dos critérios é suficiente para alterar o estado geral do sistema.

---

#### 3.5.3.1 Registro das Falhas

Quando um parâmetro não atende aos critérios definidos, ele é adicionado à lista falhas.

Exemplo:

falhas.append("Pressão dos tanques")

> A lista permite armazenar várias falhas simultaneamente.

Dessa maneira, o sistema não identifica apenas que existe um problema, mas também informa quais parâmetros apresentaram condições fora dos limites.

Ao final da validação, a função retorna: `return sistema_ok, falhas`

---

### 3.5.4 Decisão

A função `decisao_final()` recebe os resultados da validação: `def decisao_final(sistema_ok, falhas)`:

A decisão é realizada através de uma estrutura condicional.

```text
if sistema_ok == True:
    print("STATUS: DECOLAR")
else:
    print("STATUS: ABORTAR")
```

> Quando ocorre um `ABORTAR`, o programa também apresenta a quantidade e a identificação das falhas encontradas.

## 3.6 conclusão

A implementação em Python permitiu transformar os critérios de telemetria e a lógica definida no algoritmo, pseudocódigo e fluxograma em um sistema funcional de simulação para a pré-decolagem da Aurora Siger.

O programa realiza a geração dos dados de telemetria, apresenta os valores recebidos, verifica cada parâmetro individualmente e registra as condições que não atendem aos critérios estabelecidos.

Após a validação, o sistema consolida os resultados e apresenta uma decisão final:

`DECOLAR`

quando todos os parâmetros estão dentro das condições estabelecidas, ou:

`ABORTAR`

quando pelo menos um parâmetro apresenta uma condição `NOK`.

O projeto demonstra, portanto, a integração entre telemetria, definição de parâmetros, algoritmo, pseudocódigo, fluxograma e programação em Python, formando um fluxo completo de análise para a etapa de pré-decolagem da nave Aurora Siger.
